# AI use disclosure

OpenAI Codex was used as a coding and planning assistant for this project. The
student retained responsibility for the design decisions, executed every Git
commit and push, reviewed generated changes, and verified behavior on the local
M1 environment.

## Assisted work

- Converted the assignment requirements into an implementation and evidence
  checklist.
- Drafted and refined Python, Docker, Kubernetes, test, CI, and documentation
  files under the student's direction.
- Helped diagnose SeaweedFS multipart upload failures and slow inference.
- Suggested controlled experiments for training, model evaluation, HPA load
  testing, pod recovery, and fault injection.
- Helped summarize measured results while distinguishing them from assumptions.

## Representative interactions

1. Asked for the complete ordered steps required to satisfy the assignment and
   its final ZIP structure.
2. Asked the assistant to continue implementation but stop at every planned
   commit so the student could inspect, commit, and push changes personally.
3. Asked to display model-training progress and estimate completion time; this
   led to unbuffered batch progress reporting and measured timing evidence.

## Verification and limitations

AI suggestions were not treated as evidence. Claims in the report are backed by
files in `results/`, automated tests, checksums, Kubernetes state, or the
provided scoring tools. The student kit, validation labels, and provided tools
were not generated by AI. No credentials or model weights were committed to
Git. Remaining limitations, including two cold-scale timeouts in the optimized
load test, are reported rather than concealed.
